# 选题、题型路由与任务分解

## 1. 选题原则

对可选题目进行同一尺度的快速试分析，不根据“熟悉某个算法”选题。比较：

- 能否准确解释每个小问和隐含评价对象；
- 数据是否可取得、字段是否足够、许可是否允许；
- 是否能建立可解释的基线和至少一条深入路线；
- 关键参数能否估计，模型能否验证；
- 团队的数学、编程、领域知识与写作是否匹配；
- 计算量、外援依赖和时间风险是否可控；
- 是否可能形成问题特定洞察，而非通用算法展示。

先为每题写出最小闭环和最大阻塞，再决定。不要虚构对获奖率或题目难度的精确预测。

## 2. A-F 专项路由

### MCM A：连续数学

优先考虑物理/生态机理、ODE/PDE、动力系统、变分、连续优化、参数反演和数值模拟。
必须检查量纲、守恒、初边值、稳定性、收敛、网格/步长独立性和参数敏感性。
数据驱动方法可辅助，但不能无端替代可推导的机理。

### MCM B：离散数学

优先考虑图、组合、整数规划、调度、搜索、离散事件、博弈和随机离散结构。
必须检查可行性、复杂度、上下界、近似质量、重复随机实验和极端规模。
B 题不必然是优化；优化也不是 B 题专属。

### MCM C：数据洞察

优先进行数据血缘、探索分析、统计推断、预测、因果边界、机器学习和可解释性。
必须防控泄漏、过拟合、选择偏差、时间错位和不恰当随机划分；报告不确定性和实际意义。
复杂模型必须与朴素基线比较，并解释增量价值。

### ICM D：运筹与网络科学

考虑网络流、排队、路径、资源配置、中心性、社团、级联失效、韧性和运筹优化。
先定义节点、边、方向、权重、容量和动态含义；网络指标必须回答具体问题。
必须检查扰动、拓扑变化、拥堵/延迟、计算复杂度和方案可执行性。

### ICM E：可持续性

考虑系统动力学、生态/气候机理、资源流、生命周期、多目标权衡、长期情景和阈值。
区分短期拟合和长期可持续；关注反馈、延迟、存量流量、代际与区域差异。
必须检查长期极端情景、参数不确定性、尺度转换和指标之间的替代关系。

### ICM F：政策

考虑利益相关者、博弈、政策评估、成本收益、公平性、激励、执行约束和情景推演。
区分实证关系、预测和规范性判断；不得把偏好权重包装成客观事实。
必须分析不同群体影响、分配效应、意外后果、实施成本和政策稳健性。

## 3. CUMCM 与其他国赛题

不根据固定字母猜方法。按任务实质标记：`机理`、`预测`、`优化`、`评价`、`统计`、`分类聚类`、`网络`、`仿真`、`政策`或组合。

国赛常见高分风险不是缺少复杂算法，而是：题意漏答、数据处理不透明、公式与代码脱节、检验形式化、摘要无定量结果。优先消除这些风险。

## 4. 多标签任务分解

为每问标注主任务和辅助任务。例如“预测需求并制定调度”应拆成预测层、误差传播层和优化层，不能把预测点值直接当作无误差真值。

建立接口：上游输出的定义、单位、区间或分布、时间粒度和误差，必须与下游输入一致。若存在反馈，定义迭代顺序、阻尼、收敛判据和最大迭代次数。

## 5. 歧义处理

对影响结果的歧义至少提出两种合理解释，比较题面语义、领域常识、数据支持和结果差异。

可通过数据判别时先检验；无法判别时选择最保守解释并做情景对照。不得选择只让模型更容易或结果更漂亮的解释而不披露。

## 6. 团队分工与训练

建模负责人维护问题抽象、假设、公式和跨问一致性；编程负责人维护数据、实现测试、运行和结果；写作负责人维护证据链、图表、摘要和规则合规。三人共同参加模型选择与最终审查。

训练每种方法时至少完成：适用场景、使用条件、一个手算/小例、一个代码例、一个误用反例和一种验证方式。难度评价应基于所需先修、实现难度和验证难度，不编造统一学习时长。
