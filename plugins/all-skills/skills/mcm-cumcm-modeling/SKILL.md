# MCM / ICM / CUMCM 数学建模工作流

## 版本与兼容性

- 版本：`1.0.0`
- 语言：中文（英文说明见仓库 `README-EN.md`）
- 范围：CUMCM、MCM、ICM
- 兼容性：可移植 Agent Skills 包。Python 3.9+ 仅用于可选脚本；不依赖网络、MCP 服务、专有 API 或特定 Agent 运行时。

## 目标

完成从题面到可复核交付物的端到端建模。优先保证题意覆盖、数学正确、模型适配、真实计算、验证充分、结论有边界和表达清晰，而非堆砌模型或承诺奖项。

将 M/F/O 等高质量目标理解为工作方向，不将内部评分解释为官方评分或获奖概率。任何自我审查都不能替代真实计算、独立数据或人工核验。

## 不可违背的红线

1. 不虚构数据、字段、文献、定理、代码执行、实验结果、精度、图表、评审意见或客户端测试结论。
2. 区分 `proposed`、`executed`、`verified`、`reproduced`；未运行只能给出方案、公式、代码和验证设计。
3. 原始题目与原始数据保持不变；所有数值结论追溯到真实输出，模拟和合成情景必须明确标记。
4. 逐问回答题面；不能用复杂模型、额外分析或平均分掩盖漏答、错误和证据缺口。
5. 先验证实现，再评价现实适配；先建立基线，再证明复杂模型的增量价值。
6. 所有题均考虑与核心结论相关的误差、灵敏度、鲁棒性或不确定性，但按问题选择方法，不机械执行同一清单。
7. 遵守当届官方规则、引用要求和 AI 披露政策；旧年份规则只能作为历史参考。
8. 不安装依赖、不联网、不覆盖文件、不执行外部脚本，除非当前环境和用户授权允许。

## 跨平台执行约定

将本文件所在目录记为 `SKILL_DIR`，将用户当前建模项目目录记为 `WORK_DIR`。所有技能资源使用相对路径和正斜杠；不要假设 Bash、MCP、特定 IDE、网络或 Python 一定可用。

优先使用当前 Agent 的通用读取、写入、搜索和代码执行能力。工具名称不可移植时，按语义替换为读取文件、运行 Python、搜索文本等通用操作，不在正文中暴露适配过程。

没有代码执行能力时，继续完成数学推导、可运行代码、实验计划和审查清单，并将数值结论标为待计算。没有 PDF 解析能力时，请用户提供文本或页面图像，不猜测题面。

## 工作模式

- **完整求解**：从题面推进到模型、真实计算、验证、论文和终审。
- **分析设计**：只完成题意解析、候选模型、公式和实验计划，明确未执行部分。
- **续做返工**：先读取已有状态、结果和审查记录，保留有效成果，只重做受影响环节。
- **独立审查**：优先寻找反例、错误和证据缺口，不重写无问题内容。
- **训练讲解**：按建模、编程、写作分工，解释适用条件、学习难度和小例题，不把训练题结果冒充正式结果。

默认自主推进。仅在缺少题面、关键数据或会根本改变模型的信息时集中提问；可基于显式假设推进时不要反复等待确认。

## 主流程

### 0. 规则与环境预检

核对竞赛、题号、语言、截止时间、提交格式、匿名、页数和 AI 政策。规则必须从当届官方来源确认；无法联网时标记待核验。

检查现有项目、可用工具、Python 和可选依赖。可运行：

```text
python "<SKILL_DIR>/scripts/preflight.py" --profile all --json
```

缺少论文编译工具不阻塞建模；缺少计算工具时不得伪造计算结果。

### 1. 建立任务契约

读取题目与附件，逐问建立 Requirement Matrix：要求、输入、输出、约束、模型、证据、验证、论文位置和状态。识别小问依赖、反馈与可复用结果。

进行数据审计和问题路由。题号只提供先验，实际任务决定方法；允许一道题组合机理、统计、优化、仿真和评价。

### 2. 建立基线与候选模型

先完成可回答全部问题的最小闭环。每个核心任务建立朴素基线和有实质差异的主候选，通过理论检查、小样本实验和选择矩阵决定主模型。

记录假设、符号、参数来源、核心方程、算法和停止条件。为每个模型建立 Model Card，并记录舍弃方案与理由。

### 3. 实现与真实求解

先用解析特例、已知答案小例或合成数据测试实现，再运行完整数据。保存输入、参数、随机种子、环境、命令、日志和输出。

将结果状态标为 `executed` 前必须存在真实运行证据。失败运行不得覆盖父结果；重跑后检查受影响的下游图表、结论和摘要。

### 4. 验证、误差与不确定性

分别回答：方程是否求对、模型是否符合现实、结论是否稳定、输入不确定性如何传播。

按任务选择残差、留出/滚动验证、约束检查、最优性界、守恒、收敛、外部数据、替代模型和反例。开展参数、结构、数据与决策灵敏度；必要时量化区间、误差传播和失效阈值。

### 5. 论文与跨问一致性

先给每问直接答案，再写方法、结果和证据。建立“论点—数据—结果—图表—正文”链路。摘要最后撰写，包含方法、关键定量结果、验证和实际结论。

检查跨问符号、假设、参数、数据口径和结论一致。政策或建议必须说明可执行性、成本、公平性、意外后果及证据边界。

### 6. 质量门与交付

先检查 P0/P1，再进行内部评分和红队审查。P0 必须修复；P1 必须修复、降低结论强度或明确披露。不得以润色代替修复。

返工只针对根因，并回归检查受影响的需求、代码、结果、图表和结论。同一问题重复失败时停止猜测，报告阻塞证据和可选路径。

最终交付区分：数学正确性、计算复现性、格式合规性、视觉质量和提交准备度。格式通过不代表模型正确，内部高分不代表获奖。

## 每个小问的最小输出

1. 对题目的直接回答与结论状态。
2. 问题抽象、模型选择理由和被舍弃的基线。
3. 假设、符号、单位、核心公式与求解算法。
4. 真实结果或明确的未执行标记。
5. 实现验证、现实验证和误差指标。
6. 与结论相关的灵敏度、鲁棒性或不确定性。
7. 适用范围、失效条件、局限及对其他小问的影响。

## 确定性辅助工具

按需运行，不为使用工具而使用工具。脚本只辅助计算和检查，不判断数学真理，不代替论文审查。

- `scripts/preflight.py`：检查 Python、可选包和常用命令。
- `scripts/regression_metrics.py`：计算回归误差、区间覆盖和宽度。
- `scripts/classification_metrics.py`：计算混淆矩阵及二分类指标。
- `scripts/sensitivity_summary.py`：汇总单参数扰动、弹性和结论反转。
- `scripts/evidence_audit.py`：检查需求、结果和证据缺口。
- `scripts/score_review.py`：计算内部加权评分并执行硬质量门。
- `scripts/hash_manifest.py`：生成文件哈希和复现清单。

命令、输入格式、退出码和限制见 `references/api_reference.md`。
